# Repository review and agentic enhancement workflow

- Review date: 2026-11-24
- Reviewed baseline: `d7c1fb11d898b64d26ff7b9704ccd26fa954b722`
- Scope: static review of application, API, persistence, package configuration and existing documentation. This is not a security audit or a complete runtime assessment.
- Priority assumes the stated local-first prototype; public or multi-user deployment raises the security items to release blockers.

## Prioritized findings

Each entry includes the evidence, impact and a concrete next step. Line numbers refer to the reviewed baseline.

1. **Protect the local API before exposing it to a network.** `src/app/api/projects/[id]/route.ts:13-24`, `src/app/api/upload/route.ts:14-47`, `src/app/api/feedback/route.ts:5-20`, `src/app/api/sessions/[id]/events/route.ts:5-27`. Mutation routes have no authentication or authorization, and uploads accept unknown extensions and write to disk. This is a serious data-loss and disk-exhaustion risk if the service is reachable beyond a trusted machine. Define the trust boundary; for hosted use add authentication, per-project authorization, CSRF/origin protection as applicable, upload allowlisting, content validation, quotas and request size limits. Verify unauthorized reads/mutations and oversized or unsupported uploads are rejected. These safeguards do not replace network isolation for a local-only deployment.
2. **Validate project configuration at the API boundary.** `src/app/api/projects/[id]/route.ts:13-16`, `src/lib/repo.ts:126-134`, `src/app/api/projects/[id]/sessions/route.ts:9`. PATCH stores truthy nested values without runtime validation; TypeScript casts do not validate JSON. For example, a malformed `floorplan` can be persisted and later break session creation or rendering. Add versioned runtime schemas for nested config, bounds, enums and geometry; return actionable 400 errors without changing existing data. Test valid, partial and malformed updates, including invalid polygons and spawn/marker placement.
3. **Make telemetry delivery and feedback status honest.** `src/components/PlayClient.tsx:52-70,73-90,165-175`. `fetch` resolves on HTTP 4xx/5xx, so failed event batches are discarded, finalization is not retried, and feedback is marked submitted even on an error response. The 60-event queue also intentionally drops old entries. Check `response.ok`, surface feedback failure, define bounded retry/backoff and explicit drop policy, and add event IDs/deduplication before retrying uncertain deliveries. Test HTTP 500, network failure, retry/duplicate handling, and queue overflow. Page-exit `keepalive` remains best effort, not guaranteed delivery.
4. **Stop silently losing or misattributing events.** `src/app/api/sessions/[id]/events/route.ts:11-27`, `src/lib/repo.ts:179-192`, `src/db/schema.ts:38-45,54-59`, `src/app/api/feedback/route.ts:7-16`. The API reports the full filtered batch as accepted, but the repository inserts at most 60; independent foreign keys do not ensure that a session belongs to the supplied project. Also `Number(null)` is 0, so null feedback session IDs can trigger a foreign-key error rather than store NULL. Derive the project from the session, validate ownership for feedback, handle null explicitly, and reject or accurately report oversized batches. Test 60/61 events, mismatched project/session, nonexistent IDs and null session feedback.
5. **Preserve session metrics on partial or repeated updates.** `src/app/api/sessions/[id]/route.ts:9-25`, `src/lib/repo.ts:147-175`. PATCH defaults every omitted metric to zero/false/null, allowing a partial or late request to erase recorded values; finalization can also be overwritten. Update only supplied fields, validate nonnegative ranges and define idempotent finalization and ordering semantics. Test partial updates, repeated finalization and late updates.
6. **Make analytics representative and scalable.** `src/lib/repo.ts:217-257`, `src/app/page.tsx:20-25`, `src/db/schema.ts:20-65`. Event counts use an unordered 4,000-row limit, so larger datasets silently yield incomplete, unspecified counts. Completion rate includes active sessions; duration uses a different denominator. Dashboard runs full analytics per project, loading all sessions and feedback. Define metric denominators and time windows, aggregate in SQL, paginate recent rows, and add appropriate project/time indexes with a migration. Test active vs finished sessions and >4,000 events; compare query plans and results before/after.
7. **Separate synthetic data from real research and make seeding atomic.** `src/lib/repo.ts:261-268,325-387`, `src/app/page.tsx:20`, `src/app/api/projects/route.ts:5-8`. Empty databases are automatically populated with synthetic results; deleting all projects causes reseeding, while an interrupted non-transactional seed can leave partial data and suppress subsequent seeding. Sample comments and sessions are not marked as synthetic in their schema. Use explicit opt-in or durable seed state, transactionally create demos, and label/filter demo data in analytics. Test fresh DB, partial failure, repeated/concurrent seed and deletion of all projects.
8. **Add a runnable regression suite and CI.** `package.json`, `src/lib/types.ts`, `src/lib/repo.ts`, `src/app/api/`, `src/components/PlayClient.tsx`. No test script or test files are present, and no CI configuration was found. Introduce isolated temporary SQLite fixtures; cover geometry, API validation, cascades, telemetry failures, analytics and the author→play→feedback path. Run tests, lint, typecheck, migrations and build in CI. Avoid seeding or altering developer data during tests. Include browser/WebGL smoke tests where infrastructure supports them.
9. **Harden asset memory, lifecycle and provenance.** `src/app/api/upload/route.ts:16-39`, `src/app/api/assets/[name]/route.ts:28-39`, `src/lib/storage.ts:3-4`, `.gitignore`, `.data/uploads/38c3ecd3-test.ply`. Multipart data is parsed before the 90 MiB check and entire assets are buffered on upload and read; concurrent large requests can consume substantial memory. Uploads live indefinitely on local disk; the existing upload fixture is tracked and future uploads are not ignored. Set ingress/body limits, stream where supported, define orphan cleanup and backup/restore, ignore future uploads without removing tracked files automatically, and document fixture intent. Capture licenses and required attribution for bundled/user assets; `docs/adr/0001-capture-avatar-floorplan-boundaries.md` notes the bundled SOG's CC BY obligations. Validate a large asset, concurrent requests, cleanup safety and attribution.
10. **Address runtime and deployment assumptions.** `README.md:10-25`, `.env.example`, `src/db/index.ts:11-15`, `drizzle.config.ts`, `package.json`. Document supported Node versions, native build prerequisites, migration/backup/restore, persistent volume requirements, and that SQLite/local uploads are not durable shared storage in serverless/multi-instance deployments. `file:` handling strips the prefix rather than parsing a full file URL; relative directory components are intentionally discarded. Either support and test proper file URLs and paths or document the exact accepted forms. Add an `engines` policy after verifying the dependency support matrix.
11. **Restore enforceable developer checks.** `package.json`, `eslint.config.mjs`, `src/components/FloorplanEditor.tsx`, `src/components/SimCanvas.tsx`, `src/components/StudioClient.tsx`, `README.md` known limits. README reports existing React hooks/ref lint errors; fix lifecycle/ref usage rather than globally disabling rules, then make lint a required CI check. Validate engine creation/destruction, preview updates and React Strict Mode behavior. Current review could not independently run lint (see verification).
12. **Reduce agent context cost at architectural seams, not by changing behavior.** `src/lib/sim/engine.ts` (1,207 lines), `src/components/StudioClient.tsx` (800), `src/components/PlayClient.tsx` (581), `src/components/FloorplanEditor.tsx` (430), `src/lib/repo.ts` (389), `src/lib/types.ts` (359). Large mixed-responsibility files force agents to read unrelated code. Incrementally extract simulation lifecycle/input/rendering, authoring panels, telemetry transport, repository analytics/seeding, and geometry/config modules with stable imports and focused tests. Measure context tokens and task success on the same representative tasks before/after; line counts are only a proxy, not proof of token savings. No LLM integration or model prompts were identified in the reviewed source, so there is no evidence of production prompt-token usage to optimize.
13. **Reconcile documentation and feature boundaries.** `docs/adr/0001-capture-avatar-floorplan-boundaries.md`, `README.md`, `src/lib/sim/engine.ts`, `src/components/FloorplanEditor.tsx`. The ADR describes Postgres/JSONB while current persistence uses SQLite JSON-mode text; keep the historical ADR intact and add a dated superseding note/ADR. Document that bundled files in `.data/glb` and `.data/sog` are not automatically served by the uploads-only asset route, how users can select them, and how to credit assets. Existing ADR identifies missing capture calibration, placement validation and static uploaded GLB animation; use those as feature candidates, not claims that they are implemented.

## Workflow for the next agent-assisted enhancement

1. **Choose and scope:** pick one finding; record user outcome, non-goals, affected paths, assumptions, risk/trust boundary, and measurable acceptance criteria. Confirm any ambiguous product decisions before implementation.
2. **Baseline:** record commit and branch, inspect working tree, read this review plus the relevant source and ADR. Run the relevant existing checks; report environmental blockers rather than asserting success. Never include secrets or private tester data in agent context.
3. **Design:** write a short plan and list interfaces, migrations, rollback and compatibility effects. Break work into independently reviewable changes. For storage/security changes, explicitly specify failure and abuse cases.
4. **Tests first or alongside:** define at least a happy path, edge case and failure mode for each change, plus regression tests for the specific issue. Use isolated DB/filesystem fixtures. For UI behavior add an integration or browser check when feasible.
5. **Implement narrowly:** preserve unrelated work, keep domain types independent of PlayCanvas/DB, validate untrusted data at boundaries, and avoid refactoring unrelated subsystems in the same change.
6. **Verify and review:** run the targeted tests, full available suite, lint, typecheck, migrations and build; inspect the diff for security, data loss, performance and documentation drift. Report exact commands, results, and unverified items. For analytics, compare expected output against hand-calculated fixtures.
7. **Document and hand off:** update README/API docs and add an ADR for consequential decisions; summarize changed paths, evidence, tests, residual risks, migration/rollback and next task. Use the session's permitted working branch and follow repository review/PR policy.

### If a future enhancement adds LLM prompts

Define the output schema and measurable success criteria before writing each prompt. Version the prompt and changelog it. Supply the model with required source context rather than assuming repository knowledge. Include at least three reproducible cases: normal input, boundary input, and adversarial or missing-context failure. Run and record them against the actual production model, version and temperature; if unavailable, mark results unverified. Record input/output token counts and quality on a fixed evaluation set before claiming a token optimization. Do not request or store private chain-of-thought; record decisions, evidence and concise rationale instead.
